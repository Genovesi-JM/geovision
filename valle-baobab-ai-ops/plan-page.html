AI Agent Installation Plan · November 2026

Nine agents, four systems, run on what you already pay for.

A plan to operate AI agents across Kasa, Kaya Saúde and GeoVision — Azure-first, GitHub-controlled, with at most 2–3 coding agents running at once. The agents are configurations, not nine new subscriptions.

Azure + GitHub + Codex + Claude Code Staging first, humans merge Every task has a budget & an exit

01 · Foundation

The four core systems

The nine agents are configurations — instructions, restricted tools, an approved queue, a budget — built on top of these four products. Not nine pieces of software to buy.

AZURE

Automation infrastructure

Scheduled jobs, service monitoring, cloud identity, secret protection (Key Vault), cost tracking. The main cloud platform.

GITHUB

Development control center

Three repos, agent assignments, CI tests, branches, PRs, approval history, the Projects board.

OPENAI CODEX

Cloud coding & review

Works approved tasks, creates changes, reviews code without step-by-step supervision.

CLAUDE CODE

Engineering & debugging

Architecture, integrations, hard problems and Azure scripts — on the Claude Pro allowance.

On subscriptions vs. API: ChatGPT Plus and Claude Pro power interactive sessions. A custom Azure job doing unattended model calls generally needs separately metered API access — plan allowances are not unlimited API credits.

03 · Architecture

How it connects

A trigger wakes the Control Tower, which dispatches within the concurrency cap and spend limits. Every change flows through issues, branches and PRs, past automated checks and a human approval, to staging first.

Schedule · GitHub event · Azure alert
↓
Baobab Control Tower — approved backlog · priority · spend caps
↓ dispatch (max 2–3 coding agents) ↓
Coding agents (Codex / Claude Code)  +  Operations agents (Azure Jobs / model APIs)
↓
GitHub Issues → Branches → Pull Requests
↓
Automated checks (tests · security · UI) + human approval
↓
Staging first → controlled production
Installation sequence: (1) Configure Azure auth — test login before creating resources. (2) Create the GitHub board. (3) Configure agent roles in version-controlled files. (4) Connect Codex & Claude Code. (5) Add triggers (Actions + Azure Jobs). (6) Add cost, security & release controls. Creating the files does not start the agents — the platform must load them.

05 · Later

Also worth evaluating — in order, not all at once

Microsoft Foundry

Best Azure-native candidate for permanent multi-agent hosting: model selection, tools, tracing, identity.

n8n

Visual automation (API / DB / webhook / AI nodes). Self-hostable on Azure, but you maintain it.

LangGraph / LangSmith

Precise control over multi-agent workflows, persistence, routing, observability. More technical.

CrewAI · GitHub Copilot

Role-based agent teams worth testing; Copilot for assigning issues to cloud agents and async PRs ($10/mo).

Don't buy extra Copilot, Cursor, CrewAI enterprise or a paid n8n plan right now. First learn what the existing subscriptions + GitHub can do.

06 · Operation

The daily workflow

TriggerAutomated response
Every morningControl Tower checks approved tasks, reports blockers
New GitHub issueCategorize; decide if it meets automation criteria
Approved dev taskDispatch to an available coding agent
New pull requestRun unit tests, security checks, relevant UI tests
Failed CI buildAzure Sentinel / QA investigates, prepares a diagnosis
API / hosting alertInvestigate; escalate or propose a safe fix
WeeklySend business, technical and cost reports
Usage limit reachedPause new AI tasks, preserve the backlog
Never a repair loop. Every task has a max runtime, retry count, spend allowance and exit condition. If the GeoVision Azure login fails again, the system names the missing config, reports the required admin action and stops — it does not keep generating infrastructure or retrying a broken deploy.
